# Media Core

The measurement half of SonicWire's media pipeline, written in Python because the
work is numeric (EBU R128 integrated loudness, peak envelopes, frame statistics)
and the libraries that do it well are Python.

It is a **separate process**, not a library import: the Node API shells out over
HTTP so a wedged FFmpeg decode cannot take the API down with it. If the service is
absent, the product says so — no route returns a placeholder value.

## What it measures

| Endpoint | Output | Method |
| --- | --- | --- |
| `GET /health` | engine + media root | FFmpeg discovery |
| `POST /analyze` | full report | see below |

Report fields, all measured, never estimated:

- `loudness` — EBU R128 integrated LUFS, true peak (LKFS), loudness range, threshold (`loudnorm` filter).
- `silence` — segments, total seconds, ratio of runtime below −50 dBFS for ≥0.5 s (`silencedetect`).
- `blackFrames` — count, total and longest duration, at `pix_th=0.10`, `d=0.1` (`blackdetect`, first 600 s).
- `sceneCuts` — count of frames above scene score 0.3 (`select=gt(scene,0.3)`, first 600 s).
- `decode` — errors reported by a full decode pass (`-v error`), i.e. is this file actually intact.
- `signal` — mean luma and saturation over the first 30 s (`signalstats`).
- `peaks` — 400-bucket absolute peak envelope computed in numpy from 8 kHz mono PCM.

Every report carries `engine`, `measuredAt` and `notes` explaining what was skipped
(no audio stream, no video stream, scan window shorter than the file).

## Run it

```bash
cd services/media-core
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
MEDIA_ROOT=../../apps/server/var/media .venv/bin/python -m uvicorn media_core.app:app --host 0.0.0.0 --port 8791
```

Or from the repository root: `npm run dev:core`. Then point the API at it:

```bash
MEDIA_CORE_URL=http://127.0.0.1:8791 npm run dev:server
```

`FFMPEG_PATH` / `FFPROBE_PATH` are honoured, matching the Node server, so both
halves use the same binary.

## Safety

- Paths must resolve inside `MEDIA_ROOT` (default `apps/server/var/media`), or the
  request is refused with `403`. Symlinks are resolved before the check.
- Only media extensions are accepted (`415` otherwise).
- Read-only: the service never writes files, never transcodes, never deletes.
- FFmpeg runs with a timeout, in its own process group, killed with `SIGKILL` on
  expiry, so an unresponsive decode cannot leak a zombie.

## Test

```bash
cd services/media-core
FFMPEG_PATH=../../node_modules/@ffmpeg-installer/linux-x64/ffmpeg \
FFPROBE_PATH=../../node_modules/@ffprobe-installer/linux-x64/ffprobe \
.venv/bin/python -m pytest tests -q
```

Fixtures are generated by FFmpeg during the test run; no binary media is committed.
The bundled FFmpeg build in this repository predates several filter options (for
example `apad=whole_dur`), so the tests state the construct they use and why.
