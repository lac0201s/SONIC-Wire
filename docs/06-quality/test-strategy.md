# Test strategy

## Principle

Tests exist to keep claims true. Every sentence in `README.md` and
`docs/implementation-status.md` that says "verified" should be traceable to a command
whose output is quoted here or in the verification matrix.

## Layers

| Layer | Tool | What it must prove |
| --- | --- | --- |
| Contract | `vitest` (`packages/contracts`) | Schemas accept the payloads the server actually produces and reject malformed ones |
| Unit | `vitest` (`apps/server`) | Pure logic: URL guard, storage paths, ZIP writer, password hashing, queue leases |
| Integration | `vitest` + Fastify `inject` | Routes with a real SQLite database in a temp dir, real auth, real CSRF enforcement |
| Media pipeline | `vitest` + the bundled FFmpeg | Probe, thumbnail, waveform, transforms and measurements against generated fixtures |
| Service | `pytest` (`services/media-core`) | Every measurement function against FFmpeg-generated media; HTTP path guard |
| Component | Testing Library + jsdom | Design-system semantics (`Metric`, `StatusBadge`, `Waveform`, `AssetCard`) and route-level rendering with mocked API |
| Static design gate | `node scripts/check-ui-rules.mjs` | The banned-ornament list from the house rules |
| Smoke | `curl` against a running server | The real process serves, authenticates, ingests, analyses and exports |

## Rules

1. **No committed binary media.** Fixtures are generated by FFmpeg inside the test
   run. The bundled build is from 2018 and predates some filter options; tests state
   the construct they use and why (for example `apad=whole_dur` is unavailable).
2. **Skips must be visible.** A media test that cannot run because FFmpeg is missing
   reports `skipped`, never `passed`.
3. **No test asserts a zero it did not measure.** The analysis tests assert real
   numbers from a known fixture (1 s black frame, 2 scene cuts, integrated loudness in
   a plausible range).
4. **Failure paths get tests.** The 503 refusal when `media-core` is unconfigured, the
   403 path guard, CSRF rejection and unauthorised access are all exercised.
5. **Timeouts are bounded.** No test waits on the network; the only outbound calls are
   to loopback fixture servers.

## What is not covered

- No browser-driven tests: the sandbox has no Chrome/Chromium/Edge and no root to
  install one. Visual regression, real layout measurement and accessibility-tree
  checks in a real browser are unverified.
- No load or soak testing. Latency figures in the observatory are measured from real
  jobs on this machine, not from a benchmark suite.
- No fuzzing of FFmpeg inputs; the timeouts and process-group kill are tested, the
  codec attack surface is not.
